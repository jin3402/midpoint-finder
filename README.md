# 🛣️ 중간지점 찾기 (WhichFinder)

친구들과 만날 때 "어디서 볼까?" 고민하지 마세요!
**중간지점 찾기**는 앱인토스(Apps In Toss) 환경에서 동작하는 미니앱으로, 여러 명의 출발지를 입력받아 중간 위치를 찾아주고 주변의 추천 장소까지 알려주는 서비스입니다.

## ✨ 주요 기능

* **다중 출발지 입력**: 최소 2명에서 최대 6명까지 출발지를 입력할 수 있습니다.
* **중간지점 계산**: 카카오 장소 검색(Places)으로 입력한 주소·장소명을 좌표로 변환하고, 좌표들의 산술 평균으로 중간지점을 계산합니다.
* **주변 장소 추천**: 중간지점을 기준으로 카카오 카테고리 검색(맛집 `FD6` / 카페 `CE7` / 볼거리 `AT4`)을 호출합니다.
* **TDS(Toss Design System) 적용**: 토스 앱과 이질감 없는 UI를 제공합니다.

## 🧭 설계 메모

### 지도를 iframe이 아니라 SDK 직접 렌더링으로 붙인 이유

토스 미니앱 WebView는 보안 정책상 iframe을 차단합니다. iframe은 제3자 문서를 통째로 앱 안에 띄우기 때문에, 그 안에서 무엇이 로드되고 그려지는지 호스트 앱이 통제할 수 없습니다.

그래서 Kakao Maps JS SDK를 런타임에 주입해 앱이 소유한 `div`에 직접 렌더링합니다. 실행 컨텍스트가 앱 문서라 외부 리소스가 SDK 하나로 특정되고, 렌더링도 앱이 소유한 DOM 안에서 끝납니다.

* SDK를 `autoload=false`로 받고 `kakao.maps.load()`를 명시적으로 호출해 준비 시점을 제어합니다.
* 이펙트 재실행 시 스크립트가 중복 주입되지 않도록 모듈 레벨 Promise로 로딩을 싱글턴화합니다.
* SDK 로딩 실패는 지도 영역에만 표시되고, 주소 입력과 중간지점 계산은 그대로 동작합니다.

### 중간점 알고리즘: 구면 중간점 대신 산술 평균

`src/features/middle-point/geo.ts`에 두 구현이 함께 있습니다.

| 함수 | 방식 | 지원 지점 수 | 사용 |
|---|---|---|---|
| `geographicMidpoint(a, b)` | 구면(대권) 중간점 | 2개 | 미사용 |
| `arithmeticMeanLatLng(points)` | 위경도 산술 평균 | N개 | **사용 중** |

이 앱은 2~6명의 출발지를 받으므로 N개를 지원하는 산술 평균을 사용합니다. 두 방식의 차이는 수도권 이동 거리에서 무시할 수준입니다(11km 구간 약 2.2m, 29km 구간 약 14.5m). 전국 단위로 범위를 넓히면 구면 방식으로 교체하는 것이 맞고, `geographicMidpoint`는 그 판단 근거로 남겨 두었습니다.

### 카카오 카테고리 검색의 45개 상한 우회

카테고리 검색은 한 번에 15개 × 3페이지, 최대 45개까지만 반환합니다. 반경을 `3 · 6 · 10 · 15 · 20km`로 단계적으로 넓히며 여러 번 호출하고, 장소 id로 중복을 제거한 뒤 거리순으로 정렬해 최대 50곳을 모읍니다. 페이지네이션 객체가 `hasNextPage`를 주지 않는 경우에 대비해 결과 개수로 판단하는 폴백을 둡니다.

## 🛠 기술 스택

* **Framework**: React, Vite, TypeScript
* **Platform**: Apps In Toss Web Framework (WebView)
* **API**: Kakao Maps JavaScript SDK (`services` 라이브러리 — Places 검색)
* **Design**: Toss Design System (TDS)
* **기타**: TossAds 배너 / 전면 광고, `grantPromotionReward`

## 🔐 권한

기기 위치 권한을 요구하지 않습니다. 출발지를 주소·장소명 입력으로 받기 때문에 `permissions`는 빈 배열로 배포했습니다.
